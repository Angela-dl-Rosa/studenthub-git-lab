# Preguntas — Angela De la Rosa

## 1. ¿Cuál es la diferencia entre `git add` y `git commit`?

`git add` prepara los cambios para ser guardados y `git commit` guarda esos cambios en el historial del repositorio.

## 2. ¿Cuál es la diferencia entre `git push` y `git pull`?

`git push` envía los cambios al repositorio remoto y `git pull` descarga los cambios del repositorio remoto.

## 3. ¿Cuál es la diferencia entre un repositorio local y uno remoto?

El repositorio local está en nuestro computador y el remoto está almacenado en GitHub.

## 4. ¿Qué problema resuelve una rama?

Permite trabajar en cambios separados sin modificar directamente la rama principal.

## 5. ¿Qué diferencia existe entre `git merge` y `git rebase`?

`git merge` une los cambios de dos ramas, mientras que `git rebase` coloca los commits de una rama sobre una versión más reciente de otra.

## 6. ¿Por qué ocurre un conflicto?

Ocurre cuando Git encuentra cambios incompatibles en una misma parte de un archivo y no puede decidir cuál conservar.

## 7. ¿Quién debe decidir cómo resolver un conflicto?

Las personas que trabajan en el proyecto deben decidir qué cambios conservar.

## 8. ¿Qué problema resuelve un Pull Request?

Permite proponer cambios para que sean revisados antes de integrarlos a `main`.

## 9. ¿Por qué es recomendable revisar un Pull Request antes de integrarlo?

Porque permite detectar errores y comprobar que los cambios cumplen con lo esperado.

## 10. ¿Qué ventaja tiene trabajar en una rama en lugar de modificar directamente `main`?

Permite desarrollar cambios de forma independiente y mantener `main` estable.
