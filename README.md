## Preguntas de reflexión realizadas por Natalia

### 1. ¿Cuál es la diferencia entre `git add` y `git commit`?

`git add` prepara los cambios y `git commit` los guarda en el historial.

### 2. ¿Cuál es la diferencia entre `git push` y `git pull`?

`git push` sube cambios a GitHub y `git pull` baja cambios de GitHub.

### 3. ¿Cuál es la diferencia entre un repositorio local y uno remoto?

El local está en mi computador y el remoto está en GitHub.

### 4. ¿Qué problema resuelve una rama?

Permite trabajar en cambios sin afectar directamente a `main`.

### 5. ¿Qué diferencia existe entre `git merge` y `git rebase`?

`git merge` une dos ramas. `git rebase` actualiza una rama para que quede basada en la versión más reciente de otra.

### 6. ¿Por qué ocurre un conflicto?

Porque dos personas hicieron cambios diferentes en la misma parte de un archivo.

### 7. ¿Quién debe decidir cómo resolver un conflicto?

Una persona del equipo debe revisar los cambios y decidir cuál usar.

### 8. ¿Qué problema resuelve un Pull Request?

Permite enviar cambios para que otra persona los revise antes de unirlos al proyecto.

### 9. ¿Por qué es recomendable revisar un Pull Request antes de integrarlo?

Para encontrar errores y asegurarse de que los cambios estén bien.

### 10. ¿Qué ventaja tiene trabajar en una rama en lugar de modificar directamente `main`?

Permite trabajar de forma independiente sin afectar `main`.
